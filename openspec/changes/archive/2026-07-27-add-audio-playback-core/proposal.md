## Why

music-app has no code yet beyond docs. Every later phase (CLI selection, GUI
transport controls, seek/progress bar) needs a working playback engine to
build on. This is the MVP described in `initial_plan.md` Phase 1: get a
basic, functional audio player running that can load and play a single
audio file, with play/pause/stop, before anything else is layered on top.

## What Changes

- Add `src/audio_player/player.py`: an `AudioPlayer` class wrapping
  `just_playback.Playback` with `load(path)`, `play()`, `pause()`,
  `resume()`, `stop()`, `seek(seconds)`, `set_volume(level)`, and read-only
  `curr_pos`/`duration`/`playing`/`paused` properties. This is a thin
  wrapper, not a reimplementation — it exists so `src/ui` and `src/cli`
  never import `just_playback` directly, keeping the third-party dependency
  isolated to one module (module boundary already stated in `CLAUDE.md`).
- Add `src/utils.py`: `validate_music_path(path)` — checks the path exists,
  is a file, and has a supported extension (`.mp3`, `.wav`, `.flac`,
  `.ogg`). Raises a clear exception otherwise. Phase 2's directory scanner
  and any future file-loading code reuse this instead of duplicating
  validation logic.
- Add `tests/audio_player/test_player.py` and `tests/test_utils.py`: fully
  mocked (`unittest.mock.patch` on `just_playback.Playback`) per the
  project's test policy — no test requires a real audio device.
- Add `assets/test_tone.wav` generation via the `python-test-loop` skill's
  documented approach (stdlib `wave`/`struct`, deterministic sine) — used
  by tests that need a real file path and by the `run-music-app` skill's
  smoke test, not committed as a pre-made binary but generated by a small
  helper.

## Capabilities

  single audio file, with position/duration reporting.

### Modified Capabilities
(none — first capability in the project)

## Impact

- New dependency already installed: `just-playback` (see
  `requirements.txt`, `openspec/config.yaml` context for why it was chosen
  over `pygame.mixer`).
- Affected code: new files only (`src/audio_player/`, `src/utils.py`,
  `tests/`). No existing code to break.
- No GUI or CLI yet — this change is playback-engine only, consumed by CLI
  work in the next roadmap item (`add-library-scan-and-cli`).
